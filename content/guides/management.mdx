## Before the project start

Main questions that should be answered.

- Will the project be cancelled?
- Will it be used?
- How quickly will it be used?

## Cost of delay

> Opportunity costs of not building those features per unit time (day, week, month ...). That's how you can prioritize the features.

## High performance program management

Principles

1. Measurable outcomes at the program level.
2. Teams work to design and test hypotheses.
3. Fast feedbacks.
4. Small batches.
5. Culture of experimentation.

### Impact mapping

- Create an idea. <Muted>Reduce transaction cost by 10%</Muted>
- Decide who can help or will be touched with this idea. <Muted>How stakeholders can help or hinder that outcome being achieved.</Muted>
- What? <Muted>What we can do to achieve this.</Muted>

### Hypothesis-driven delivery

We believe that <Muted>\[building this feature\] \[for these people\]</Muted> <br/> will achieve <Muted>\[this outcome\]</Muted>. <br/> We will know that we are successful when we see <Muted>\[this signals from users\]</Muted>

### Experiments

- Surveys
- A/B testing
- Usability.
